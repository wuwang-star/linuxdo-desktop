# LinuxDo Desktop 桥接扩展

伴生 MV3 浏览器扩展（零构建、零依赖）：把浏览器里 linux.do 的 `_t` 登录 cookie 自动同步到 LinuxDo Desktop 桌面客户端——「浏览器登录一次，应用自动跟随」。

## Edge 安装（加载解压缩，一次性）

1. 打开 Edge，地址栏输入 `edge://extensions` 回车。
2. 打开左下角（或左侧栏）的**「开发人员模式」**开关。
3. 点击**「加载解压缩的扩展」**，选择本仓库的 `extension/` 目录（即本文件所在目录）。
4. 工具栏出现扩展图标（可在拼图菜单里固定）。Chromium 系浏览器（Chrome 等）步骤相同（`chrome://extensions`）。

## 配对流程

1. 在应用中打开**登录页 → 方式二卡片 → 「Edge 扩展桥接」**，打开开关。应用会显示一个 **6 位数字配对码**并开始监听本机回环端口 `127.0.0.1:17366`。
2. 点击浏览器里的扩展图标，在弹窗中粘贴配对码，点**「保存配对码」**（只需一次，存于扩展本地）。
3. 在浏览器里登录 linux.do（或已有登录态时刷新页面触发 cookie 续期）。
4. `_t` cookie 一有变化，扩展自动推送到应用，应用登录态随之更新（登录页轮询 5s，约 10s 内可见）。

弹窗中的**「立即推送」**用于手动补推（例如应用刚开启桥接时）。

## 工作原理

- `background.js`（service worker）：`chrome.cookies.onChanged` 监听 domain 为 linux.do 且 name 为 `_t` 的 cookie 写入（1.5s 防抖合并），带配对码 `POST http://127.0.0.1:17366/ingest`，请求体 `{"pairCode":"123456","tCookie":"..."}`。
- 应用侧校验配对码（错误返回 401），合法则走与「手动粘贴 _t」完全相同的注入通道并刷新登录态，返回 `{"ok":true,"username":"..."}`。
- MV3 service worker 会被休眠，cookie 变化事件会自动唤醒它，无常驻需求。

## 安全边界

- 只读取 `linux.do` 域的 `_t` 一个 cookie，其余 cookie 一律不碰。
- `_t` 只在推送瞬间经内存转发，**不写入** `chrome.storage`、不打印日志；扩展本地只存配对码与最近一次推送结果摘要。
- 接收口仅绑定 `127.0.0.1`，不暴露局域网；配对码错误一律 401 拒绝；应用里可随时「重新生成」配对码（旧码立即失效）或关闭桥接（端口停止监听）。
- 配对码是弱凭据，仅防本机其他程序误撞；如不信任本机环境请勿开启。

## 卸载 / 回退

`edge://extensions` 里移除本扩展即可；应用侧关闭「Edge 扩展桥接」开关即停止监听。删除仓库 `extension/` 目录不影响应用其余功能。
